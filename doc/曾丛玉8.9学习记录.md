# 8.9 STM32 模块化开发问题记录

## 1. led_flow 模块链接失败问题

### 问题现象

在 Task2 添加流水灯模块后，编译出现：

```
Undefined symbol config_apply
Undefined symbol led_flow_run
```

同时出现：

```
implicit declaration of function 'led_flow_run'
```

程序无法完成链接。

---

### 问题原因

虽然已经创建：

```
user/
├── inc
│   └── led_flow.h
└── src
    └── led_flow.c
```

但是 Keil 工程没有正确加入 `led_flow.c` 文件。

C语言工程中：

* `.h` 文件负责函数声明
* `.c` 文件负责函数实现

如果 `.c` 文件没有加入工程，编译阶段可能通过，但是链接阶段无法找到函数。

---

### 解决方法

检查 Keil 工程：

```
MDK-ARM/keil_proj_demo.uvprojx
```

确认：

```
user/src/led_flow.c
```

已经加入 Source Group。

同时在 main.c 添加：

```c
#include "led_flow.h"
```

重新编译。

---

### 最终结果

Build成功：

```
0 Error(s)
0 Warning(s)
```

流水灯模块正常运行。

# 2. Task2功能理解偏差问题

## 问题现象

完成 Task2 后，观察实际运行效果：

```
LED1 快闪三次
LED2 快闪三次
LED3 快闪三次
LED4 快闪三次
蜂鸣器响一次
```

但是最开始理解成普通流水灯：

```
LED1
 ↓
LED2
 ↓
LED3
 ↓
LED4
```

感觉和作业要求不一致。

---

## 问题原因

开始设计时只考虑了 LED 顺序移动，没有按照任务要求拆分：

Task2：

* 每个 LED 单独运行
* 每个 LED 闪烁三次
* 完成后蜂鸣提示

Task3：

* 将闪烁过程封装为 blink 模块
* 流水灯调用 blink

---

## 解决方法

重新调整模块关系：

```
main.c

   |
   |

led_flow

   |
   |

blink

   |
   |

led driver
```

其中：

LED模块负责硬件控制。

blink模块负责：

* 闪烁次数
* 点亮时间
* 熄灭时间

led_flow模块负责：

* LED执行顺序

---

## 最终结果

程序结构符合任务要求。

main.c中只调用：

```c
led_flow_run();
```

不直接控制 LED。

# 3. Git提交内容错误问题

## 问题现象

完成 Task2 后查看提交：

```bash
git show --stat HEAD
```

发现提交内容只有：

```
doc/8.9reference
```

文件移动。

但是实际修改：

```
Core/Src/main.c
user/inc/led_flow.h
user/src/led_flow.c
MDK-ARM/keil_proj_demo.uvprojx
```

没有进入提交。

---

## 问题原因

第一次提交时，只提交了文件移动操作。

后续修改虽然存在于工作区，但是没有执行：

```bash
git add
```

所以没有进入 commit。

Git提交只记录暂存区内容。

---

## 解决方法

查看状态：

```bash
git status
```

发现：

```
modified:
Core/Src/main.c
user/inc/led_flow.h
user/src/led_flow.c
MDK-ARM/keil_proj_demo.uvprojx
```

重新加入：

```bash
git add .
```

修改最近一次提交：

```bash
git commit --amend --no-edit
```

---

## 最终结果

再次查看：

```bash
git show --stat HEAD
```

显示：

```
Core/Src/main.c
MDK-ARM/keil_proj_demo.uvprojx
user/inc/led_flow.h
user/src/led_flow.c
```

提交内容正确。

# 4. blink模块引入错误问题

## 问题现象

添加 blink 模块后，编译出现：

```
unknown type name 'blink_state_t'
```

以及：

```
use of undeclared identifier 'blink_cfg_t'
```

同时：

```
implicit declaration of function 'blink'
```

---

## 问题原因

blink.h 中类型定义顺序错误。

例如：

结构体中使用：

```c
blink_state_t state;
```

但是前面没有定义：

```c
typedef enum
{

} blink_state_t;
```

导致编译器无法识别类型。

---

## 解决方法

调整 blink.h 定义顺序：

先定义枚举：

```c
typedef enum
{

} blink_state_t;
```

再定义结构体：

```c
typedef struct
{

blink_state_t state;

} blink_handle_t;
```

同时确认：

```c
#include "blink.h"
```

路径正确。

---

## 最终结果

重新编译：

```
0 Error(s)
0 Warning(s)
```

blink模块成功加入工程。

# 5. 蜂鸣器模块结构理解问题

## 问题现象

开始不知道蜂鸣器代码应该放在哪里。

已有：

```
hardware/
├── inc
│   └── buzzer.h
└── src
    └── buzzer.c
```

不知道 Task6 的控制代码是否应该直接放入 buzzer.c。

---

## 问题原因

没有区分驱动层和功能层。

已有：

```
hardware/src/buzzer.c
```

属于硬件驱动。

负责：

```c
buzzer_on();
buzzer_off();
```

只操作 GPIO。

但是：

什么时候响？

属于应用逻辑。

---

## 解决方法

保持：

```
hardware/src/buzzer.c
```

只负责硬件控制。

新增：

```
user/src/buzzer_ctrl.c
```

负责：

* 根据流水灯状态控制蜂鸣器
* 管理响铃逻辑

---

## 最终结果

模块结构变为：

```
main.c

 |
 +---- led_flow

 |
 +---- buzzer_ctrl

 |
 +---- buzzer driver
```

各模块职责明确。
