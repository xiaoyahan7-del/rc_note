# 题目一：环形队列实现

## 1. 学习内容

环形队列是一种常用的数据缓冲结构，可以解决生产者和消费者速度不一致的问题。

本次队列使用：

- head：指向当前读取位置；
- tail：指向下一次写入位置；
- count：记录当前元素数量。

通过 count 区分队列为空和队列已满。

---

## 2. 实现过程

完成了以下函数：

### packet_queue_init()

用于初始化队列：

- head 清零；
- tail 清零；
- count 清零。

初始化后队列为空。

---

### packet_queue_push()

实现数据入队：

流程：

1. 判断队列是否已满；
2. 将数据写入 tail 指向的位置；
3. tail 加一；
4. 到达队尾后回到 0；
5. count 增加。

---

### packet_queue_pop()

实现数据出队：

流程：

1. 判断队列是否为空；
2. 从 head 位置读取数据；
3. head 加一；
4. 到达队尾后循环；
5. count 减少。

---

## 3. 遇到的问题

开始理解环形队列时容易把 head 和 tail 的含义混淆。

通过调试发现：

- head 不是最后一个读取位置，而是当前读取位置；
- tail 不是最后一个写入位置，而是下一次写入位置。

采用这种设计可以避免移动大量数据，提高效率。

# 题目二：位运算封包

## 1. 学习内容

通信协议通常不会直接发送多个变量，而是将多个信息压缩到一个数据字段中。

本次实验将：

- 闪烁次数；
- LED编号；

组合成一个 command 字节。

数据格式：

```

高4位：blink_count
低4位：led_mask

````

---

## 2. 实现方法

使用：

```c
(blink_count << 4) | led_mask
````

完成命令组合。

例如：

闪烁次数：

```
3
```

LED：

```
0001
```

组合：

```
0011 0001
```

即：

```
0x31
```

---

## 3. 校验和

封包时计算：

```
checksum = header[0] + header[1] + cmd
```

只保留低8位。

作用：

接收端可以判断数据是否发生错误。

---

# 题目三：位运算解包

## 1. 学习内容

解包是封包的逆过程。

接收到数据后，需要：

1. 检查协议头；
2. 检查校验和；
3. 提取命令信息。

---

## 2. 包头检查

两个 header 字节组合：

```c
(header[0] << 8) | header[1]
```

得到：

```
0x0A5A
```

与规定值比较。

---

## 3. 校验和检查

重新计算：

```c
PACKET_CHECKSUM(header[0],
                header[1],
                cmd)
```

并与接收到的 checksum 比较。

如果不一致，说明数据错误。

---

## 4. 数据解析

通过位运算恢复：

闪烁次数：

```c
cmd >> 4
```

LED掩码：

```c
cmd & 0x0F
```

# 调试过程

## 1. 编译错误

初始编译时出现函数没有返回值：

```
non-void function does not return a value
```

原因：

`command_pack_unpack()` 定义返回 bool 类型，但是函数末尾没有 return。

解决：

补充：

```c
return true;
```

或者错误情况下：

```c
return false;
```

---

## 2. 下载问题

编译成功：

```
0 Error(s)
```

但是下载失败：

```
No ST-LINK detected
```

原因：

电脑没有检测到 ST-LINK 下载器。

重新连接开发板后即可。
