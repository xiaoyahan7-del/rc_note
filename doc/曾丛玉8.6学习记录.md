# Git仓库初始化

第一次操作时出现了Git初始化目录错误。

原本在：

```
D:\Course\Robot
```

目录下执行了：

```bash
git init
```

导致整个Robot文件夹被Git管理。

实际需要管理的工程目录是：

```
D:\Course\Robot\8.6\keil_proj_demo-main
```

解决方法：

1. 删除错误目录中的 `.git` 文件夹；
2. 进入正确工程目录；
3. 重新执行：

```bash
git init
```

重新建立正确的Git仓库。

通过这次错误理解了：

> Git仓库的位置由执行 `git init` 的目录决定，因此初始化前必须确认当前路径。

# 第一次提交

进入正确工程目录后，执行：

```bash
git add .
git commit -m "first commit"
```

完成第一次版本提交。

作用：

- `git add`：告诉Git哪些文件需要保存；
- `git commit`：生成一个版本节点，记录当前工程状态。

# Git分支管理

创建功能分支：

```bash
git checkout -b feature-blink
```

作用：

创建独立开发环境，不影响主分支。

在 `feature-blink` 分支中继续修改代码：

```c
#define BLINK_TIMES 6U
```

提交：

```bash
git add Core/Src/main.c

git commit -m "feature分支调整闪烁次数"
```

之后切回主分支：

```bash
git checkout master
```

合并分支：

```bash
git merge feature-blink
```

理解了：

- master用于保存主要版本；
- feature分支用于开发新功能；
- 完成功能后通过merge合并。

# GitHub远程仓库操作

创建GitHub仓库后，将本地仓库连接到远程：

```bash
git remote add origin 仓库地址
```

查看远程仓库：

```bash
git remote -v
```

然后上传代码：

```bash
git push -u origin master
```

成功后，本地工程同步到了GitHub：

仓库地址：

```
https://github.com/xiaoyahan7-del/keil_proj_demo
```

# 遇到的问题及解决方法

## 1. Git初始化目录错误

问题：

在错误目录执行：

```bash
git init
```

导致父目录被Git管理。

解决：

删除错误`.git`文件夹，在工程目录重新初始化。

---

## 2. 删除index.lock失败

出现：

```
rm: cannot remove '.git/index.lock': Device or resource busy
```

原因：

Git进程或者VS Code占用了锁文件。

解决：

关闭相关程序后重新操作。

---

## 3. LF和CRLF换行提示

出现：

```
LF will be replaced by CRLF
```

原因：

Windows和Linux使用不同换行格式。

理解：

- LF：Linux常用换行；
- CRLF：Windows常用换行。

该提示不会影响代码提交。
