## 作业四：状态机设计理解

### 1. 为什么使用状态机

在前面的 LED 控制程序中，程序逻辑主要通过 `while(1)` 中不断执行固定代码实现：

例如：

```c
while(1)
{
    LED1闪烁;
    LED2闪烁;
    蜂鸣器报警;
}
```

这种方式功能较少时可以实现需求，但是当系统增加更多功能，例如：

* 待机状态
* 工作状态
* 报警状态
* 错误状态

如果继续使用大量 `if-else` 判断，会导致代码结构混乱，不方便维护。

因此引入状态机(State Machine)，将系统划分为多个独立状态，每个状态负责自己的行为。

---

### 2. 状态机组成

本次实验设计了三个状态：

| 状态            | 功能   |
| ------------- | ---- |
| STATE_IDLE    | 空闲状态 |
| STATE_RUNNING | 运行状态 |
| STATE_ALARM   | 报警状态 |

状态转换关系：

```
        +-------------+
        |             |
        v             |
    STATE_IDLE
        |
        |
        v
 STATE_RUNNING
        |
        |
        v
 STATE_ALARM
        |
        |
        +-------> STATE_IDLE
```

---

### 3. 状态函数设计

每个状态对应一个处理函数：

```c
static void state_idle_run(void);

static void state_running_run(void);

static void state_alarm_run(void);
```

这样每个状态只负责自己的任务。

例如：

空闲状态：

```c
led_off(0xF8);

HAL_Delay(1000);

current_state = STATE_RUNNING;
```

表示：

* 关闭所有 LED
* 等待 1 秒
* 自动进入运行状态

运行状态：

```c
LED1亮
LED2亮
LED3亮
LED4亮
```

表示流水灯效果。

报警状态：

```c
四个LED同时亮灭
```

模拟报警。

---

### 4. 状态表思想

程序中使用函数指针数组：

```c
static const state_func_t state_table[STATE_COUNT]
=
{
    [STATE_IDLE] = state_idle_run,
    [STATE_RUNNING] = state_running_run,
    [STATE_ALARM] = state_alarm_run
};
```

这样：

```c
state_table[current_state]();
```

即可执行当前状态对应函数。

相比：

```c
if(state==IDLE)
{
    idle();
}
else if(state==RUNNING)
{
    running();
}
```

代码更加简洁。

---

### 5. 本次实验收获

通过状态机设计，实现了：

* 状态与功能分离
* 降低程序耦合
* 提高代码可维护性
* 为后续嵌入式复杂系统开发提供基础

在实际嵌入式项目中，例如：

* 智能车控制
* 机器人控制
* 通信协议处理

都会大量使用状态机思想。

# 作业五：模块化设计理解

## 1. 模块化设计思想

随着工程规模增加，如果所有代码都写在 `main.c` 中，会导致：

* 文件过长
* 修改困难
* 功能之间互相影响

因此采用模块化设计：

```
project

├── hardware
│     ├── led.c
│     └── buzzer.c
│
├── common
│     └── command_pack_queue.c
│
├── user
│     └── state_machine.c
│
└── Core
      └── main.c
```

不同模块负责不同功能。

---

## 2. LED模块

LED相关操作封装：

```c
led_on();

led_off();
```

main.c 不需要知道：

* GPIO端口
* 引脚编号
* HAL库调用方式

只需要调用接口即可。

例如：

```c
led_on(LED1_PIN);
```

实现了：

"面向接口编程"

---

## 3. 命令协议模块

通过：

```c
command_pack_create()
```

完成命令封装。

数据格式：

```
+--------+--------+------+----------+
|Header1 |Header2 | CMD  | checksum |
+--------+--------+------+----------+

```

其中：

```
CMD高4位
    |
    闪烁次数

CMD低4位
    |
    LED编号
```

例如：

```c
command_pack_create(
    &pkt,
    3,
    LED_MASK_LED1
);
```

表示：

LED1闪烁3次。

---

## 4. 环形队列设计

采用：

```
head
 |
 v

[ ][ ][ ][ ]

        ^
        |
       tail
```

通过：

```c
head
tail
count
```

三个变量管理。

优点：

* 不需要移动数据
* 插入删除效率高
* 适合嵌入式实时系统

---

## 5. 状态机与模块结合

最终系统结构：

```
main.c

 |
 |
 v

state_machine

 |
 |
 v

led/buzzer

```

main只负责：

```c
while(1)
{
    state_machine_run();
}
```

具体功能由不同模块完成。

这种结构符合实际嵌入式工程开发方式。
