# 二、GitHub HTTPS 连接问题分析


## 1. 遇到的问题

在 8.7 STM32 工程上传 GitHub 时，使用：

```bash
git push
```

上传代码。

但是出现：

```
Failed to connect to github.com:443
```

说明 Git 使用 HTTPS 连接 GitHub 时失败。


首先检查网络：

```bash
ping github.com
```


测试结果显示可以收到 GitHub 回复，说明电脑可以访问 GitHub。

但是：

- 浏览器可以访问 GitHub
- ping 可以成功
- Git push 仍然失败

说明问题可能出现在 Git HTTPS 连接方式或者网络环境。


---

## 2. 查看 Git 代理配置


检查 Git 是否设置代理：

```bash
git config --global --get http.proxy

git config --global --get https.proxy
```


如果没有输出：

说明 Git 没有设置代理。


经过排查，发现 HTTPS 连接 GitHub 不稳定，因此考虑使用 SSH 方式连接。


---

# 三、HTTPS 和 SSH 的区别


## 1. HTTPS 方式


之前使用的远程地址：

```
https://github.com/用户名/仓库名.git
```


特点：

优点：

- 配置简单
- 初学 Git 时容易使用


缺点：

- 网络环境不好时容易连接失败
- 长时间开发使用体验较差


---

## 2. SSH 方式


SSH 是一种安全通信协议。

GitHub 支持通过 SSH Key 进行身份认证。


SSH 地址：

```
git@github.com:用户名/仓库名.git
```


SSH 不使用账号密码，而是通过密钥验证身份。


验证过程：

```
本地电脑
    |
    | 使用私钥认证
    |
GitHub服务器
    |
    | 使用保存的公钥验证
    |
允许访问仓库
```


SSH 更适合长期开发使用。


---

# 四、SSH Key 原理


SSH Key 包含两个部分：

## 1. 私钥


例如：

```
id_rsa
```


私钥保存在自己的电脑中。


作用：

- 证明自己的身份
- 进行身份认证


注意：

私钥不能泄露。


---

## 2. 公钥


例如：

```
id_rsa.pub
```


公钥需要上传到 GitHub。


GitHub 保存公钥后，可以验证本地电脑发送的连接请求。


---

## 3. SSH 的优势


使用 SSH 后：

- 不需要每次输入账号密码
- 身份验证更加安全
- 适合长期管理代码仓库

# 五、HTTPS 切换 SSH


查看当前远程仓库：

```bash
git remote -v
```


原来的地址：

```
https://github.com/xiaoyahan7-del/rc_note.git
```


修改为 SSH：

```bash
git remote set-url origin git@github.com:xiaoyahan7-del/rc_note.git
```


再次查看：

```bash
git remote -v
```


如果显示：

```
git@github.com:xiaoyahan7-del/rc_note.git
```


说明已经切换成功。


之后：

```bash
git push
```

会通过 SSH 方式上传。

# 六、LF 和 CRLF 换行符问题


## 1. 问题出现


在提交 STM32 工程文件时出现提示：

```
LF will be replaced by CRLF
```


这个提示不是错误。

它表示 Git 发现当前文件换行格式和 Windows 环境存在差异。


---

## 2. LF 和 CRLF 区别


不同操作系统使用不同的换行方式。


Linux 和 macOS：

```
LF
```

表示：

```
\n
```


Windows：

```
CRLF
```

表示：

```
\r\n
```


例如：

Linux：

```
hello\n
```


Windows：

```
hello\r\n
```


虽然显示效果一样，但是 Git 会认为文件内容存在差异。


---

# 七、使用 core.autocrlf 解决换行问题


Windows 环境推荐设置：

```bash
git config --global core.autocrlf true
```


查看配置：

```bash
git config --global core.autocrlf
```


输出：

```
true
```


说明配置成功。


---

## core.autocrlf true 的作用


设置以后：

Windows 工作区：

```
CRLF
```

提交到 Git：

```
LF
```


从 Git 下载：

```
LF
```

转换到 Windows：

```
CRLF
```


Git 会自动完成换行符转换。


---

## 使用这个配置的好处


1. 保证 Git 仓库内部格式统一

2. 避免不同系统之间产生大量无意义修改

3. 减少 git diff 出现大量换行变化

4. 提高多人协作时的代码稳定性


对于 STM32 工程来说：

工程中包含大量：

- `.c`
- `.h`
- `.uvprojx`

文件。

统一换行格式可以减少版本管理问题。

# 九、实际开发中遇到的 Git 问题总结


## 1. 命令输入错误


错误：

```bash
git remove-v
```


原因：

记错 Git 命令。


正确查看远程仓库：

```bash
git remote -v
```


删除远程仓库：

```bash
git remote remove origin
```


---

## 2. commit 后没有 push


查看状态：

```bash
git status
```


出现：

```
Your branch is ahead of 'origin/master' by 1 commit
```


说明：

- 本地已经提交
- 但是远程仓库还没有更新


解决：

```bash
git push
```


---

## 3. 修改文件后忘记添加


查看：

```bash
git status
```


出现：

```
modified:
```


说明：

文件已经修改，但是没有加入提交。


正确流程：

```bash
git add .

git commit -m "修改说明"

git push
```


---

## 4. Git push 网络失败


遇到：

```
Failed to connect to github.com:443
```


解决思路：

1. 检查网络：

```bash
ping github.com
```


2. 检查代理：

```bash
git config --global --get http.proxy

git config --global --get https.proxy
```


3. 如果 HTTPS 不稳定，可以切换 SSH。
