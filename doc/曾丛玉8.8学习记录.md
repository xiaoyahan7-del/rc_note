# 三、SSH 连接 GitHub 学习


## 1. 为什么使用 SSH

之前使用 HTTPS 方式：

```
https://github.com/用户名/仓库.git
```

上传代码时需要通过 HTTPS 连接 GitHub。


实际使用过程中出现：

```
Failed to connect to github.com:443
```

说明 HTTPS 连接 GitHub 的 443 端口不稳定。


因此学习使用 SSH 方式。


---

# 2. SSH 工作原理


SSH（Secure Shell）是一种安全通信协议。


GitHub SSH 认证过程：

```
本地电脑
    |
    |
SSH密钥认证
    |
    |
GitHub服务器
```


SSH 使用一对密钥：

## 私钥

保存：

```
本地电脑
```


不能公开。


## 公钥

上传：

```
GitHub账户
```


上传代码时：

GitHub 使用公钥验证本地电脑是否拥有对应私钥。

验证成功后允许上传。


---

# 3. 测试 SSH 是否成功


输入：

```bash
ssh -T git@github.com
```


成功显示：

```
Hi username!
You've successfully authenticated
```


说明：

- SSH 密钥配置成功；
- GitHub 可以识别当前电脑。


---

# 4. HTTPS切换SSH


原来的远程地址：

```
https://github.com/xiaoyahan7-del/rc_note.git
```


修改为 SSH：

```bash
git remote set-url origin git@github.com:xiaoyahan7-del/rc_note.git
```


查看：

```bash
git remote -v
```


显示：

```
origin git@github.com:xiaoyahan7-del/rc_note.git
```


之后：

```bash
git push
```

即可通过 SSH 上传。

# 四、LF 和 CRLF 换行符学习


## 1. 什么是换行符


不同操作系统保存文本时，换行方式不同。


Linux：

```
LF
```

表示：

```
\n
```


Windows：

```
CRLF
```

表示：

```
\r\n
```


区别：

|系统|换行方式|
|-|-|
|Linux|LF|
|Windows|CRLF|


---

# 2. Git 中遇到的问题


提交代码时出现：

```
warning:
LF will be replaced by CRLF
```


例如：

```
warning: in the working copy of
'main.c',
LF will be replaced by CRLF
```


说明：

当前文件使用 LF 格式，

但是 Windows 环境会转换成 CRLF。


这不是编译错误，只是换行格式提示。


---

# 3. core.autocrlf 配置


执行：

```bash
git config --global core.autocrlf true
```


作用：

提交代码：

```
Windows(CRLF)
        |
        |
Git仓库(LF)
```


下载代码：

```
Git仓库(LF)
        |
        |
Windows(CRLF)
```


这样可以保证：

- Git仓库保持统一格式；
- Windows编辑代码正常；
- 减少换行符导致的无意义代码变化。

# 六、本次遇到的 Git 错误总结


## 错误1：命令输入错误


输入：

```bash
git remove-v
```


错误：

```
git: 'remove-v' is not a git command
```


原因：

Git不存在该命令。


正确：

查看远程仓库：

```bash
git remote -v
```


---

# 错误2：HTTPS连接失败


错误：

```
Failed to connect to github.com:443
```


原因：

HTTPS访问GitHub失败。


解决：

切换SSH：

```bash
git remote set-url origin git@github.com:xiaoyahan7-del/rc_note.git
```


---

# 错误3：忘记添加新文件


例如：

```
user/inc/alarm_sys.h
user/src/alarm_sys.c
```


状态：

```
Untracked files
```


原因：

文件没有加入Git。


解决：

```bash
git add .
```


然后：

```bash
git commit -m "add alarm system module"
```


---

# 错误4：修改代码后没有提交


查看：

```bash
git status
```


显示：

```
modified:
main.c
```


说明：

文件修改存在，但是没有保存版本。


正确流程：

```
修改代码
    |
git add
    |
git commit
    |
git push
```


---

# 错误5：STM32工程缺少文件导致编译错误


STM32工程中：


`.h`

负责：

```
函数声明
```


`.c`

负责：

```
函数实现
```


如果删除 Include Path：

错误：

```
led.h file not found
```


如果删除源文件：

错误：

```
Undefined symbol
```


说明：

头文件和源文件必须同时存在。

# 七、学习总结


通过 8.6、8.7、8.8 阶段学习，掌握了完整 Git 工程管理流程：


```
创建仓库
    |
添加文件
    |
commit保存版本
    |
绑定远程仓库
    |
push上传GitHub
```


同时理解：


1. Git 不只是代码备份工具，而是记录工程开发过程的版本管理工具；

2. STM32工程需要同时管理：
   
   - `.c`
   - `.h`
   - Keil工程文件
   - 文档文件


3. SSH 相比 HTTPS 更适合长期开发，可以避免部分网络连接问题；

4. LF 和 CRLF 是不同操作系统的换行格式差异，不属于代码错误；

5. 遇到 Git 问题时，应优先检查：

```bash
git status

git remote -v
```

- STM32工程版本管理；
